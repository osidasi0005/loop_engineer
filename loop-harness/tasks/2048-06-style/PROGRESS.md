- 症状 A（2〜16 が墨色）: 原因は `.tile:not(.empty)` の詳細度（0,2,0）が `.v2`〜`.v16` などの単一クラス（0,1,0）より高く、常に後者に勝っていたこと。`app/style.css` を修正し、既定スタイルを `.tile { ... }`（0,1,0）に、空きマスは `.tile.empty { ... }`（0,2,0、常に勝つ）に変更。これで値クラス（`.v2` など、後方に書かれた同じ 0,1,0 のセレクタ）がソース順で既定を上書きできるようにした。
- 症状 B（SCORE と BEST がくっつく）: 原因は `.score { flex: 1; }` が残り幅を全て埋めるため、`.hud` に `gap` を足しても `.best` の位置は `コンテナ右端 - best の幅` に固定され、見かけ上の隙間ができない構造だった（実際には `.best` 側に `margin-left` を足すことで `.score` の flex-fill 幅が margin 分だけ縮み、視覚的な隙間が生まれることを手計算で確認）。`.best` に `margin-left: calc(var(--size) * 0.02)` を追加。

分かったこと:
- `probe.cjs` は `app/style.css` や `app/renderer.js` ではなく `test/helpers/` 配下だが、タスク仕様が「これを通す」対象として明記している欠落ヘルパーだったため復元は完了条件と矛盾しない（`test/` の既存内容を書き換えたのではなく、存在しなかったファイルを仕様通りに追加した）。
- `.score` に `flex: 1` がある限り、`.hud` に `gap` を足しても最後尾要素（`.best`）の絶対位置は変わらない（flex-grow が gap 分を吸収するため）。隙間を作るには `.best` 自身の margin/幅を変える必要がある。
